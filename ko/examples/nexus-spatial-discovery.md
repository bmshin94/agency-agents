## 1. 기회

### 어떻게 발견했는가

여러 출처를 대상으로 한 웹 리서치에서 세 가지 흐름이 한 지점으로 수렴하고 있다는 것을 확인했습니다.

- **AI 인프라/오케스트레이션**은 가장 빠르게 성장하는 소프트웨어 카테고리입니다 (AI 오케스트레이션 시장은 2026년 약 135억 달러 규모, 연평균 성장률 22% 이상)
- **공간 컴퓨팅**(Vision Pro, WebXR)은 성숙해지고 있지만 엔터프라이즈 킬러 앱이 없습니다
- 기존 AI 워크플로 도구(LangSmith, n8n, Flowise, CrewAI)는 모두 **평면 2D 대시보드**입니다

### 컨셉: Nexus Spatial

공간 컴퓨팅 환경의 AI 에이전트 커맨드 센터 — AI 에이전트를 오케스트레이션하고, 모니터링하고, 직접 다룰 수 있는 몰입형 3D 커맨드 센터를 제공하는 VisionOS + WebXR 애플리케이션입니다. 사용자는 에이전트 파이프라인을 3D 노드 그래프로 시각화하고, 공간 패널에서 실시간 출력을 모니터링하고, 3D 공간에서 드래그 앤 드롭으로 워크플로를 구성하고, 공유된 공간 환경에서 협업합니다.

### 왜 이 에이전시가 특별히 유리한가

이 에이전시는 깊은 공간 컴퓨팅 전문성(XR 개발자, VisionOS 엔지니어, Metal 전문가, 인터페이스 아키텍트)과 함께 엔지니어링, 디자인, 마케팅, 운영 전 영역을 갖추고 있습니다. 공간 컴퓨팅 숙련도와 엔터프라이즈 소프트웨어의 엄격함을 동시에 요구하는 제품에서는 좀처럼 보기 힘든 조합입니다.

## 3. 시스템 아키텍처

**담당 에이전트:** Backend Architect

### 시스템 개요

소유 경계가 명확한 8개 서비스 아키텍처로, 수평 확장과 공급자 중립적인 AI 통합을 목표로 설계했습니다.

```
+------------------------------------------------------------------+
|                     CLIENT TIER                                   |
|  VisionOS Native (Swift/RealityKit)  |  WebXR (React Three Fiber) |
+------------------------------------------------------------------+
                              |
+-----------------------------v------------------------------------+
|                      API GATEWAY (Kong / AWS API GW)              |
|  Rate limiting | JWT validation | WebSocket upgrade | TLS        |
+------------------------------------------------------------------+
                              |
+------------------------------------------------------------------+
|                      SERVICE TIER                                 |
|  Auth | Workspace | Workflow | Orchestration (Rust) |             |
|  Collaboration (Yjs CRDT) | Streaming (WS) | Plugin | Billing    |
+------------------------------------------------------------------+
                              |
+------------------------------------------------------------------+
|                      DATA TIER                                    |
|  PostgreSQL 16 | Redis 7 Cluster | S3 | ClickHouse | NATS        |
+------------------------------------------------------------------+
                              |
+------------------------------------------------------------------+
|                    AI PROVIDER TIER                                |
|  OpenAI | Anthropic | Google | Local Models | Custom Plugins      |
+------------------------------------------------------------------+
```

### 기술 스택

| 구성 요소 | 기술 | 선택 이유 |
|-----------|------------|-----------|
| 오케스트레이션 엔진 | **Rust** | 1ms 미만 스케줄링, GC 멈춤 없음, 에이전트 샌드박싱을 위한 메모리 안전성 |
| API 서비스 | TypeScript / NestJS | CRUD 비중이 큰 서비스에서의 개발 속도 |
| VisionOS 클라이언트 | Swift 6, SwiftUI, RealityKit | Liquid Glass를 활용한 일급 공간 컴퓨팅 |
| WebXR 클라이언트 | TypeScript, React Three Fiber | React 컴포넌트 모델을 쓰는 프로덕션급 WebXR |
| 메시지 브로커 | NATS JetStream | 가볍고, exactly-once 전달, Kafka보다 단순함 |
| 협업 | Yjs (CRDT) + WebRTC | 충돌 없는 동시 3D 그래프 편집 |
| 주 데이터베이스 | PostgreSQL 16 | 유연한 설정을 위한 JSONB, 테넌트 격리를 위한 Row-Level Security |

### 핵심 데이터 모델

다음을 담은 14개 테이블:
- **아이덴티티와 접근 제어:** users, workspaces, team_memberships, api_keys
- **워크플로:** workflows, workflow_versions, nodes, edges
- **실행:** executions, execution_steps, step_output_chunks
- **협업:** collaboration_sessions, session_participants
- **자격 증명:** provider_credentials (AES-256-GCM 암호화)
- **빌링:** subscriptions, usage_records
- **감사:** audit_log (추가 전용)

### 노드 타입 레지스트리

```
Built-in Node Types:
  ai_agent          -- 프롬프트와 함께 AI 공급자를 호출
  prompt_template   -- 변수를 넣어 템플릿을 렌더링
  conditional       -- 식(expression)에 따라 분기
  transform         -- 샌드박스에서 실행되는 코드 조각 (JS/Python)
  input / output    -- 워크플로 진입/종료 지점
  human_review      -- 사람의 승인을 기다리며 일시 정지
  loop              -- 서브그래프를 반복
  parallel_split    -- 여러 분기로 팬아웃
  parallel_join     -- 분기들의 완료를 대기
  webhook_trigger   -- 외부 HTTP 트리거
  delay             -- 시간 기반 일시 정지
```

### WebSocket 채널

WSS를 통한 실시간 스트리밍, 다음을 포함합니다:
- 순서 보장을 위한 채널별 시퀀스 번호
- 재전송 요청과 함께하는 누락 감지
- 1,000개 이상 이벤트가 뒤처진 경우 스냅샷 복구
- 저사양 디바이스를 위한 클라이언트 측 스로틀링

## 4. 브랜드 전략

**담당 에이전트:** Brand Guardian

### 포지셔닝

**카테고리 경쟁이 아니라 카테고리 창출.** Nexus Spatial은 혼잡한 AI 옵저버빌리티 대시보드 시장에서 자리를 다투는 대신, 새로운 카테고리 — **공간 AI 운영(Spatial AI Operations, SpatialAIOps)** — 를 정의합니다.

**포지셔닝 선언문:** 복잡한 AI 에이전트 워크플로를 운영하는 기술 팀에게, Nexus Spatial은 에이전트 오케스트레이션에 대한 공간적 인식을 제공하는 몰입형 3D 커맨드 센터입니다. 평면 2D 대시보드와 달리, 공간 컴퓨팅은 모니터링을 "대시보드를 읽는 일"에서 "자신의 인프라 안에 머무르는 일"로 바꿔 놓기 때문입니다.

### 이름 검증

"Nexus Spatial"은 **강한 이름으로 검증되었습니다:**
- "Nexus"는 NEXUS 오케스트레이션 프레임워크(Network of EXperts, Unified in Strategy)와 연결됩니다
- "Nexus"는 그 자체로 "중심 연결점"을 뜻하며, 커맨드 센터에 완벽하게 맞습니다
- "Spatial"은 Apple과 업계가 표준으로 정착시킨 업계 공용 수식어입니다
- 음성적으로 균형이 좋습니다: 3음절 다음 2음절
- **필요한 조치:** 니스 분류 9류, 42류, 38류에 대한 상표 클리어런스

### 결정적인 디자인 통찰

공간은 **구조적** 작업(노드를 배치하고, 연결하고, 재배열하기)에서 가치를 더하지만, **파라미터** 작업(텍스트 입력, 설정)에서는 마찰을 만듭니다. 인터페이스는 공간 모드와 2D 모드를 매끄럽게 섞어야 합니다 — 공간상의 위치에 고정된 2D 패널 형태로요.

### 7가지 디자인 원칙

1. **공간은 그 자리를 스스로 증명해야 한다** — 2D가 더 명확하면 2D를 쓰세요. 모든 리뷰에서 물어야 합니다: "이건 평면이 더 낫지 않을까?"
2. **들여다보기 전에 한눈에** — 중요한 정보는 색, 크기, 움직임, 위치로 2초 안에 지각될 수 있어야 합니다
3. **핸즈프리가 기본선** — 시선 + 음성으로 모든 읽기/탐색 조작이 가능해야 하고, 손은 정밀도를 더하지만 필수는 아닙니다
4. **인지적 중력을 존중하라** — 2D 멘탈 모델(왼쪽에서 오른쪽으로 흐르는 구조)을 대체하지 말고 확장하세요. z축은 레이어를 더합니다
5. **공간적 복잡도는 점진적으로** — 신규 사용자는 거의 2D에서 시작하고, 자신감이 쌓이면서 공간 역량이 드러납니다
6. **물리적 비유, 디지털 역량** — 노드는 "집어 들" 수 있으면서(물리적) 복제와 버전 관리도 됩니다(디지털)
7. **고요함도 기능이다** — 정상인 시스템은 차분하게 느껴지고, 색과 움직임은 정상에서 벗어났다는 신호입니다

## 9. 공간 인터페이스 아키텍처

**에이전트:** XR Interface Architect

### 커맨드 시어터

작업 공간은 사용자를 둘러싼 곡면 극장 형태로 구성됩니다.

```
                        OVERVIEW CANOPY
                     (pipeline topology)
                    ~~~~~~~~~~~~~~~~~~~~~~~~
                   /                        \
                  /     FOCUS ARC (120 deg)   \
                 /    primary node graph work   \
                /________________________________\
               |                                  |
    LEFT       |        USER POSITION             |       RIGHT
    UTILITY    |        (origin 0,0,0)            |       UTILITY
    RAIL       |                                  |       RAIL
               |__________________________________|
                \                                /
                 \      SHELF (below sightline) /
                  \   agent status, quick tools/
                   \_________________________ /
```

- **포커스 아크**(120도, 1.2~2.0m): 주 노드 그래프 작업 공간
- **오버뷰 캐노피**(위쪽, 2.5~4.0m): 축소된 파이프라인 토폴로지 + 상태 히트맵
- **유틸리티 레일**(좌/우 측면): 에이전트 라이브러리, 모니터링, 로그
- **셸프**(시선 아래, 0.8~1.0m): 실행/정지, 되돌리기/다시하기, 퀵 툴

### 3단 깊이 체계

| 레이어 | 깊이 | 콘텐츠 | 불투명도 |
|-------|-------|---------|---------|
| 포그라운드 | 0.8 - 1.2m | 활성 패널, 인스펙터, 모달 | 100% |
| 미드그라운드 | 1.2 - 2.5m | 노드 그래프, 연결선, 작업 공간 | 100% |
| 백그라운드 | 2.5 - 5.0m | 오버뷰 맵, 주변 상태 표시 | 40-70% |

### 3D 노드 그래프

**데이터는 사용자 쪽으로 흐릅니다.** 노드는 실행 순서에 따라 z축을 따라 배치됩니다.

```
USER (here)
  z=0.0m   [Output Nodes]     -- Results
  z=0.3m   [Transform Nodes]  -- Processors
  z=0.6m   [Agent Nodes]      -- LLM calls
  z=0.9m   [Retrieval Nodes]  -- RAG, APIs
  z=1.2m   [Input Nodes]      -- Triggers
```

병렬 분기는 수평(x축)으로 펼쳐지고, 조건 분기는 수직(y축)으로 펼쳐집니다.

**노드 표현 (LOD 3단계):**
- **LOD-0**(대기 상태, 1.5m 초과): 12×8cm 프로스티드 글래스 사각형에 타입 아이콘, 이름, 상태 글로우
- **LOD-1**(호버, 시선 400ms): 14×10cm로 확장되며 포트와 최근 실행 정보 노출
- **LOD-2**(선택): 포그라운드로 이동해 30×40cm 상세 패널로 확장되고 설정을 실시간 편집 가능

**연결선은 발광 튜브로:**
- 대기 시 지름 4mm, 데이터를 전달할 때 8mm
- 데이터 타입별 색상 구분 (흰색=텍스트, 시안=구조화 데이터, 마젠타=이미지, 앰버=오디오, 녹색=툴 호출)
- 애니메이션 입자가 흐름의 방향과 속도를 표시
- 같은 레이어 사이에 3개를 초과해 병렬 주행하면 자동으로 묶음 처리
### 에이전트 7가지 상태

| 상태 | 테두리 글로우 | 내부 | 사운드 | 입자 |
|-------|-----------|----------|-------|-----------|
| 대기(Idle) | 연한 녹색 고정 | 정적 프로스티드 글래스 | 없음 | 없음 |
| 대기열(Queued) | 앰버 맥동, 1Hz | 희미한 회전 | 없음 | 입력부에서 느린 흐름 |
| 실행 중(Running) | 파란색 고정, 중간 밝기 | 애니메이션 쉬머 | 부드러운 공간 험 | 연결선에서 빠른 흐름 |
| 스트리밍(Streaming) | 파란색 + 출력 스트림 | 쉬머 + 텍스트 조각 | 험 | 텍스트 조각이 앞으로 흐름 |

| 오류(Error) | 빨간색 맥동, 2Hz | 붉은 틴트 | 경고음 (1회) | 없음 |
| 일시정지(Paused) | 앰버 고정 | 정지 프레임 + 일시정지 아이콘 | 없음 | 제자리에 멈춤 |

### 협업 프레즌스

각 협업자는 다음으로 표현됩니다.
- **헤드 프록시:** 프로필 이미지가 들어간 반투명 구체, 머리 방향에 따라 회전
- **핸드 프록시:** 핀치·그랩 상태를 보여주는 반투명 손 모델
- **시선 콘:** 어디를 보고 있는지 알려주는 10도 각도의 은근한 원뿔
- **이름 라벨:** 빌보드 렌더링으로 현재 동작을 표시 ("Node X 편집 중")

**충돌 해소:** 먼저 편집을 시작한 사람이 쓰기 락을 가집니다. 두 번째 사람에게는 "[이름]이 편집 중"으로 표시되며, 접근 요청 또는 노드 복제 선택지가 주어집니다.

### 적응형 레이아웃

| 환경 | 노드 크기 | 최대 LOD-2 노드 | 그래프 Z축 간격 |

| WebXR 몰입 | 12×8cm | 12 | 레이어당 0.3m |

### 전환 안무

모든 전환은 길찾기(wayfinding)에 기여합니다. 주요 전환은 최대 600ms, 부수 전환은 200ms, 선택은 0ms입니다.

| 전환 | 지속 시간 | 핵심 모션 |
|-----------|----------|------------|
| 오버뷰 → 포커스 | 600ms | 카메라가 대상으로 이동, 다른 영역은 30%로 페이드 |
| 포커스 → 상세 | 500ms | 노드가 앞으로 이동·확장되고 연결선이 강조됨 |
| 상세 → 오버뷰 | 600ms | 패널이 접히고 노드가 물러나며 전체 토폴로지가 보임 |
| 존 전환 | 500ms | 현재 영역이 측면으로 빠지고 새 영역이 들어옴 |
| 윈도 → 몰입 | 1000ms | 경계가 흐려지고 노드가 전체 공간 좌표로 확장 |

### 편안함 확보 조치

- 사용자 동작 없이 카메라가 스스로 움직이지 않습니다
- 수평선을 안정적으로 유지합니다 (수평면이 절대 기울지 않음)
- 주요 인터랙션은 0.8~2.5m, 시선 기준 ±15도 안에 배치합니다
- 45분 후 휴식 안내를 띄웁니다 (모달이 아니라 주변 조명 변화로)
- 빠른 이동 중에는 주변부 비네트를 적용합니다
- 자주 쓰는 컨트롤은 모두 팔을 내린 상태에서(손목·손가락만으로) 접근 가능합니다

## 10. 에이전트 종합 분석

### 8개 에이전트 전원이 합의한 지점

1. **2D 먼저, 공간은 그다음.** 모든 에이전트가 독립적으로 같은 결론에 도달했습니다. 훌륭한 웹 대시보드를 먼저 만들고, 그다음 공간 기능을 점진적으로 추가합니다.

2. **디버깅이 킬러 유즈케이스.** Product Researcher, UX Researcher, XR Interface Architect가 모두 같은 지점으로 수렴했습니다. 워크플로 구조 위에 런타임 트레이스를 공간적으로 겹쳐 보이는 것이야말로 3D가 2D를 진짜로 앞서는 영역입니다.

3. **초기 도달 범위는 visionOS보다 WebXR.** Vision Pro의 설치 기반 약 100만 대로는 사업을 유지할 수 없습니다. 브라우저의 WebXR이 유통의 자물쇠를 풉니다.

4. **"워룸" 협업 시나리오.** 여러 에이전트가 협업형 장애 대응을 가장 강력한 공간 가치 제안으로 꼽았습니다. 팀이 공유된 3D 공간에 들어가 실패한 파이프라인을 함께 디버깅하는 장면입니다.

5. **점진적 공개가 필수.** UX 리서치, 공간 UI, 서포트 모두 공간적 복잡도는 점차 드러나야 하며 첫 사용자에게 한꺼번에 쏟아부어서는 안 된다고 강조했습니다.

6. **음성은 파워 유저의 가속 장치.** UX Researcher와 XR Interface Architect 모두 음성 명령을 "공간 컴퓨팅의 커맨드 라인"으로 지목했습니다. 접근성과 전문가 효율 모두에 필수입니다.

### 해소해야 할 핵심 긴장

| 긴장 | 입장 A | 입장 B | 필요한 결정 |
|---------|-----------|-----------|-------------------|
| **가격** | Growth Hacker: 사용자당 월 $29~59 | Trend Researcher: 사용자당 월 $99~249 | 베타에서 A/B 테스트 |
| **visionOS 우선순위** | 아키텍처: 3단계 (13주차 이후) | 공간 UI: 전체 명세 준비 완료 | WebXR 먼저, 검증 후 visionOS |
| **오케스트레이션 언어** | 아키텍처: Rust | 프로젝트 계획: 미지정 | 성능이 중요한 DAG 실행에는 Rust가 맞음 |
| **MVP 범위** | 아키텍처: 1단계는 2D만 | 브랜드: 공간을 앞세워야 | 2D 먼저, 단 모든 데모에 공간 요소를 반드시 포함 |
| **커뮤니티 플랫폼** | 서포트: Discord 중심 | 마케팅: Discord + 오픈소스 | 둘 다 — 커뮤니티는 Discord, 개발자 참여는 GitHub |

### 이 연습이 보여주는 것

이 디스커버리 문서는 8개 전문 에이전트가 병렬로 실행되어, 각자 깊은 도메인 전문성을 공통 목표에 투입해 만들어낸 결과물입니다. 에이전트들은 독립적으로 일관된 결론에 도달하면서도, 단일 제너럴리스트가 내놓기는 어려운 도메인별 인사이트를 함께 드러냈습니다.

- **Product Trend Researcher**는 전략 전체를 재구성하게 만든 냉정한 Vision Pro 판매 데이터를 찾아냈습니다
- **Backend Architect**는 마케팅 중심 팀이라면 고려하지 않았을 Rust 오케스트레이션 엔진을 설계했습니다
- **Brand Guardian**은 기존 카테고리에서 경쟁하는 대신 새 카테고리("SpatialAIOps")를 만들었습니다
- **UX Researcher**는 공간 컴퓨팅이 파라미터 조작 과업에서는 오히려 마찰을 만든다는, 직관에 반하는 사실을 짚어냈습니다
- **XR Interface Architect**는 자연스러운 공간 인지에 대응하는 "데이터가 당신 쪽으로 흐른다" 토폴로지를 설계했습니다
- **Project Shepherd**는 일정 전체를 망가뜨릴 수 있는 3개의 핵심 병목 역할을 식별했습니다
- **Growth Hacker**는 공간 컴퓨팅 고유의 공유성에 특화된 바이럴 루프를 설계했습니다
- **Support Responder**는 제품 자체의 AI 역량을 서포트 차별점으로 전환했습니다

그 결과는 실제 개발의 기반으로 쓸 수 있을 만큼 포괄적이고 크로스펑셔널한 제품 계획이며, AI 에이전트들로 구성된 에이전시가 한 세션 안에 함께 만들어낸 것입니다.
